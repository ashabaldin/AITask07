# Переоценка товаров через сервис объектов — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** маршрут `POST /hs/objects/prices/reprice` переоценивает товары на процент с даты, повтор с той же датой не меняет цены; каждое правило ТЗ — тест YAxUnit, написанный до кода.

**Architecture:** в существующем расширении `СчетаМагазина` (`Extensions/Bills`) — новый шаблон URL и однострочный обработчик в HTTP-сервисе, вся логика — в новом общем модуле `СчетаМагазинаПереоценка`. Тесты — новые модули `ТестыЮнит` и `ТестыИнтеграция` в расширении `Тесты`.

**Tech Stack:** 1С:Предприятие 8.5.1.1529, BSL, файловая ИБ, YAxUnit 25.12, PowerShell-скрипт `tools/run-tests.ps1`.

**Spec:** `docs/superpowers/specs/2026-11-10-repricing-design.md` (утвержден). Читать вместе с планом.

## Global Constraints

- Основную конфигурацию (`Config/`) не менять. Новое расширение не создавать.
- В существующих объектах Bills разрешено только: шаблон `Переоценка` (`/prices/reprice`, POST, обработчик `Переоценить`) в `HTTPServices/СчетаМагазина.xml` и функция `Переоценить` в модуле HTTP-сервиса; регистрация нового модуля в `Extensions/Bills/Configuration.xml`. Остальные существующие модули не трогать.
- Имена метаданных и комментарии — с `е`, не `ё`.
- Общие модули тестов: `Сервер` = true, `Глобальный` и `ВызовСервера` = false.
- Пути в JSON-конфигах YAxUnit — только с обратным слешем (`C:\\...`).
- Команды 1С — из PowerShell; после правки расширения — загрузка в ИБ, затем прогон.
- Red: тест падает на своем утверждении (заглушка возвращает пустой результат по контракту, не исключение). Red и Green — отдельные коммиты. Прошедший с первого прогона тест не переписывается до падения: в этом плане он помечается **[охранный]** и коммитится с этой пометкой в сообщении.
- Сигнатуры платформенных методов, в которых нет уверенности, сверять через MCP `bsl-platform-context` (agents.md); API YAxUnit — по исходникам 25.12.
- Коммиты — на русском, с завершающей строкой `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. Тестовый товар создается с `ОбменДаннымиЗагрузка = Истина` — тогда `ПриЗаписи` справочника не пишет автоматическую цену 0 и после удаления товара не остается записи регистра со ссылкой на него. **Это уточнение реализации к пункту дизайна «автоматическую запись регистрируем к удалению»: записи просто не возникает.** Проверяется в Task 8 (запрос к регистру после полного прогона).
2. Ключи записей, созданных проверяемым кодом, регистрируются к удалению **до** утверждений — иначе после красного прогона записи останутся (Task 4–7).
3. Ошибка входа не пишет в регистр ничего, даже если часть товаров валидна (Task 7: валидный товар + процент 150).
4. Повторы, группы, помеченные на удаление и неверные UUID в `items` дают `items[i]`, а не общую ошибку (Task 7, тесты без отдельного Red).
5. Тело не JSON / не объект — `400`, `path: null`, а не `500` (Task 7).
